# ConfPlanner

ConfPlanner — персональный self-hosted AI-агент в Telegram для поиска, проверки и
отслеживания научных конференций. Бот помогает хранить научные интересы, находить подходящие
мероприятия, проверять официальные страницы, собирать даты и дедлайны, вести список
отслеживаемых конференций и заранее напоминать о важных сроках.

Сам Telegram-бот является AI-чатом. Отдельной кнопки «AI-чат» нет: владельцу достаточно
написать вопрос или задачу обычным сообщением. Для частых операций предусмотрено постоянное
меню.

Проект рассчитан на одного владельца. Сообщения других пользователей отклоняются до запуска
основной логики агента.

## Возможности

- обычный диалог с моделью прямо в Telegram;
- подключение Ollama Cloud с разрешённым списком бесплатных моделей;
- подключение собственного локального или приватного OpenAI-совместимого API;
- переключение провайдера и модели через `/model` без перезапуска контейнера;
- поиск конференций через внутренний SearXNG;
- поиск по научным темам, ключевым словам, региону, году и пользовательским правилам;
- переход с каталогов конференций на отдельные страницы мероприятий;
- извлечение названия, места, дат проведения, официальной ссылки и дедлайнов;
- независимая проверка извлечённых данных другим агентом;
- список кандидатов с последовательным просмотром по одной карточке;
- отдельные решения «Отслеживать», «Пропустить» и «Отклонить»;
- долговременная память с произвольными заметками и предпочтениями;
- SQL-граф знаний по темам, конференциям, источникам, дедлайнам и заметкам;
- подтверждение владельцем всех операций, изменяющих данные;
- автоматическая проверка конференций и новый поиск каждый понедельник;
- ежедневная проверка приближающихся дедлайнов;
- сохранение выполняемых workflow и восстановление после перезапуска;
- безопасные промежуточные статусы в Telegram во время долгого поиска;
- локальная статистика обращений и токенов Ollama Cloud.

## Что умеет агент

Агент может:

1. Запомнить научные интересы, регионы, приоритеты и ограничения.
2. Сформировать поисковые запросы по темам пользователя.
3. Найти страницы конференций и каталоги мероприятий.
4. Перейти по связанным страницам официального сайта.
5. Извлечь даты проведения, место, регистрацию и сроки подачи тезисов.
6. Сопоставить конференцию с научными интересами владельца.
7. Исключить прошедшие, дублирующиеся и нерелевантные мероприятия.
8. Показать кандидата с источником и результатами проверки.
9. После подтверждения сохранить конференцию и включить мониторинг.
10. Повторно проверять страницу и сообщать об изменениях.
11. Напоминать о дедлайнах за указанное число дней.

Агент не считает данные сохранёнными только потому, что модель написала об этом в чате.
Сообщение об успешной записи формируется только после фактической транзакции и повторного
чтения сохранённых строк из базы данных.

## Архитектура

Docker Compose запускает два сервиса:

1. `confplanner` — Python-приложение с Telegram-ботом, планировщиком, MCP-сервером,
   агентной логикой и прикладными сервисами.
2. `searxng` — внутренний метапоиск для поиска конференций в интернете.

Основной процесс ConfPlanner включает:

- aiogram long polling;
- APScheduler для периодических задач;
- встроенный MCP Streamable HTTP сервер на `127.0.0.1`;
- ограниченный цикл вызова инструментов моделью;
- SQLite как источник истины;
- Alembic для автоматических миграций;
- безопасную загрузку и очистку веб-страниц;
- долговечные многошаговые workflow.

MCP-порт и SearXNG не публикуются наружу. Модель не получает shell, файловую систему, raw SQL,
секреты или неограниченный инструмент загрузки произвольных URL.

## Мультиагентная система

Длительное исследование выполняют несколько ролей:

- координатор строит ограниченный план работы;
- исследователь ищет страницы и извлекает факты;
- проверяющий независимо сверяет факты и цитаты;
- детерминированный валидатор решает, какие значения разрешено записать;
- сервис сохранения фиксирует проверенные изменения в SQLite.

Для ролей можно выбрать разные модели:

```dotenv
AGENT_SUPERVISOR_MODEL=
AGENT_RESEARCH_MODEL=
AGENT_VERIFIER_MODEL=
AGENT_FALLBACK_MODEL=
```

Пустое значение означает использование модели, выбранной владельцем через `/model`.

Состояние запуска, задачи, промежуточные артефакты и безопасные события прогресса хранятся в
SQLite. После перезапуска продолжаются только незавершённые задачи, допускающие повтор.

## Требования

Для запуска необходимы:

- Linux-сервер, компьютер или VM с Docker Engine;
- Docker Compose v2;
- исходящий доступ к Telegram, модели, поисковым системам и сайтам конференций;
- токен Telegram-бота от `@BotFather`;
- числовой Telegram ID владельца;
- хотя бы один источник моделей:
  - API-ключ Ollama Cloud, или
  - собственный OpenAI-совместимый API;
- свободное место для Docker-образов и SQLite volume.

Для запуска без Docker дополнительно нужны Python 3.12+ и `uv`.

## Быстрый запуск

Клонируйте репозиторий:

```bash
git clone https://github.com/annaromanovskaya/conference-planner.git ConfPlanner
cd ConfPlanner
```

Создайте рабочий файл конфигурации:

```bash
cp .env.example .env
```

Заполните в `.env` Telegram-настройки и хотя бы один профиль модели. После этого запустите
контейнеры:

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 -f confplanner
```

Откройте бота в Telegram и отправьте:

```text
/start
/model
```

Выберите модель. Бот выполнит безопасную проверку поддержки инструментов. Модель без tool
calling можно использовать для обычного чата, но она не сможет полноценно управлять
конференциями.

## Создание Telegram-бота

1. Откройте `@BotFather`.
2. Выполните `/newbot`.
3. Сохраните полученный токен в `TELEGRAM_BOT_TOKEN`.
4. Узнайте свой числовой Telegram ID.
5. Запишите его в `OWNER_TELEGRAM_ID`.

Пример:

```dotenv
TELEGRAM_BOT_TOKEN=YOUR_TELEGRAM_BOT_TOKEN
OWNER_TELEGRAM_ID=YOUR_TELEGRAM_ID
```

Не отправляйте токен Telegram и API-ключи в чат бота и не добавляйте `.env` в Git.

## Подключение моделей

### Ollama Cloud

```dotenv
OLLAMA_CLOUD_BASE_URL=https://ollama.com
OLLAMA_CLOUD_API_KEY=YOUR_OLLAMA_CLOUD_API_KEY
OLLAMA_CLOUD_FREE_MODELS=gemma4:31b,gpt-oss:120b,gpt-oss:20b,nemotron-3-nano:30b,nemotron-3-super,nemotron-3-ultra
```

В `/model` показываются только модели, которые одновременно:

- присутствуют в ответе Ollama `/api/tags`;
- перечислены в `OLLAMA_CLOUD_FREE_MODELS`.

ConfPlanner не покупает usage credits и не переключается на платные модели автоматически.
Кнопка «Настройки» показывает локально зафиксированные запросы и токены, но это не остаток
лимита аккаунта. Точный процент Free usage доступен только на официальной странице
[Ollama Usage](https://ollama.com/settings/usage), ссылка на которую есть в боте.

Если в аккаунте Ollama разрешено платное списание, ConfPlanner не может самостоятельно
запретить его. Это настраивается в аккаунте Ollama.

### Собственный локальный API моделей

Этот профиль используется, если у вас есть собственный локальный, LAN, VPN или приватный API
моделей. API должен быть совместим с OpenAI и предоставлять:

- `GET /v1/models`;
- `POST /v1/chat/completions`;
- OpenAI-совместимые tool calls;
- желательно `response_format` с JSON Schema.

Настройка:

```dotenv
LLM_LOCAL_BASE_URL=http://llm-server.local:1337/v1
LLM_LOCAL_API_KEY=YOUR_LLM_LOCAL_API_KEY
```

Важно:

- адрес обычно должен заканчиваться на `/v1`;
- в адрес не надо добавлять `/models` или `/chat/completions`;
- адрес должен быть доступен из Docker-контейнера;
- `127.0.0.1` внутри контейнера указывает на сам контейнер, а не на хост;
- используйте доступный LAN/VPN IP или DNS-имя;
- ключ отправляется как `Authorization: Bearer ...`;
- если сервер не требует ключ, оставьте `LLM_LOCAL_API_KEY` пустым;
- логин и пароль от веб-панели не используются, если API не преобразует их в Bearer-токен.

Профиль не отображается в `/model`, пока `LLM_LOCAL_BASE_URL` пуст.

После обновления старой установки переименуйте в рабочем `.env`:

```text
LLM_HUB_BASE_URL  -> LLM_LOCAL_BASE_URL
LLM_HUB_API_KEY   -> LLM_LOCAL_API_KEY
```

Миграция базы автоматически изменит сохранённый ID профиля `llm-hub` на `llm-local`.

## Основные переменные `.env`

Все поддерживаемые значения и комментарии находятся в `.env.example`.

```dotenv
# Telegram
TELEGRAM_BOT_TOKEN=YOUR_TELEGRAM_BOT_TOKEN
OWNER_TELEGRAM_ID=YOUR_TELEGRAM_ID

# Лимиты агента
AGENT_MAX_STEPS=6
AGENT_MAX_TOOL_CALLS_PER_STEP=3
AGENT_TIMEOUT_SECONDS=300
TRACKED_CHECK_TIMEOUT_SECONDS=300
AGENT_MAX_CONTEXT_CHARS=24000
AGENT_MAX_TOOL_RESULT_CHARS=12000
AGENT_WORKFLOWS_ENABLED=true

# Внутренний MCP
MCP_HOST=127.0.0.1
MCP_PORT=8765

# Хранилище и поиск
DATABASE_URL=sqlite+aiosqlite:////data/conference_scout.db
SEARXNG_URL=http://searxng:8080
READER_FALLBACK_URL=https://r.jina.ai

# Расписание
DISCOVERY_HOUR=10
MONITORING_INTERVAL_HOURS=72
REMINDER_HOUR=9
REMINDER_DAYS=30,14,7,3,1,0

# Время и фильтрация
MIN_RELEVANCE_SCORE=0.5
APP_TIMEZONE=Europe/Moscow
LOG_LEVEL=INFO
```

Оставляйте `MCP_HOST=127.0.0.1`: MCP является внутренней границей приложения, а не публичным
API.

После изменения `.env` пересоздайте контейнер:

```bash
docker compose up -d --build --force-recreate confplanner
```

Выбор модели через `/model` сохраняется в базе и не требует перезапуска.

## Команды Telegram

- `/start` — показать главное меню и краткую справку;
- `/model` — выбрать подключение и модель;
- `/new` — начать новый диалог, сохранив долговременную память;
- `/memory` — показать подтверждённые записи памяти;
- `/forget ID` — предложить удалить запись памяти;
- `/help` — показать подсказку.

Главное меню:

- «Мои темы» — научные направления владельца;
- «Найти конференции» — полный цикл проверки и нового поиска;
- «Конференции» — сохранённые конференции, число кандидатов и архив;
- «Ближайшие дедлайны» — будущие сроки, сгруппированные по конференциям;
- «Источники» — каталоги и сайты научных организаций;
- «Настройки» — модель, время запуска и статистика Ollama.

Если после обновления Telegram продолжает показывать старую клавиатуру, отправьте `/start`.
Постоянная клавиатура хранится клиентом Telegram, пока бот не заменит её новой.

## Память и граф знаний

История диалога хранится в SQLite и при росте заменяется безопасным summary. `/new` начинает
новый диалог, но не удаляет долговременную память.

Долговременная память хранит:

- научные интересы;
- предпочтительные регионы;
- запрещённые регионы;
- приоритетные сообщества и конференции;
- бюджетные правила;
- произвольные заметки владельца.

Фразы «Запомни», «Учти», «Не предлагай», «Я занимаюсь» и «Мне интересны» распознаются до
общего агентного цикла. Бот создаёт предложение записи и показывает кнопки подтверждения.

Каждая запись содержит исходный текст, валидированное правило, область применения и источник
происхождения. `/memory` показывает сохранённые записи, а `/forget ID` предлагает удалить
конкретную запись.

SQL-граф знаний связывает темы, конференции, источники, дедлайны, подписки и заметки без
отдельной графовой базы данных.

## Подтверждение действий

Любая операция записи сначала создаёт pending action. Подтверждение требуется для:

- добавления темы;
- добавления источника;
- сохранения или удаления памяти;
- импорта кандидата;
- включения отслеживания;
- изменения дедлайна;
- архивирования конференции.

Просроченное, отменённое, чужое или уже выполненное действие нельзя выполнить повторно.

## Поиск конференций

Кнопка «Найти конференции» и естественный запрос запускают единый цикл:

1. Проверить отслеживаемые конференции, если наступил срок мониторинга.
2. Пересмотреть кандидатов, ранее помеченных «Пропустить».
3. Проверить настроенные источники.
4. Выполнить новый поиск через SearXNG.
5. Исключить прошедшие события, дубли, отклонённые и нерелевантные результаты.
6. Сохранить новых кандидатов.
7. Показать первого кандидата для решения владельца.

Поиск может переходить на следующие страницы выдачи и менять русские и английские
формулировки запросов. Глубоко проверяются наиболее перспективные результаты, а не только
первые ссылки.

Во время долгой операции одно Telegram-сообщение обновляется безопасными статусами: страница
поиска, открытый источник, этап проверки и количество найденных кандидатов. Параллельный
дубликат того же исследования не запускается.

## Карточки кандидатов

Кандидаты показываются по одному. В карточке могут быть:

- название;
- даты проведения;
- место;
- тематическая релевантность;
- дедлайны;
- официальная ссылка;
- исходная страница;
- статус проверки;
- замечания проверяющего.

Доступные действия:

- «Отслеживать» — проверить, сохранить и включить мониторинг после подтверждения;
- «Подробнее» — открыть исходную или официальную страницу;
- «Пропустить» — отложить кандидата до следующего допустимого пересмотра;
- «Отклонить» — исключить конференцию из обычного повторного поиска.

Списки пропущенных и отклонённых конференций не выводятся постоянно, но агент может показать
их по прямому запросу владельца.

## Проверка данных

Проверенный снимок кандидата содержит нормализованное название, даты, место, официальный URL,
дедлайны, цитаты, источники и оценку релевантности.

Проверка выполняется в два этапа:

1. Детерминированный фильтр проверяет дату события и совпадение с ключевыми словами.
2. Исследователь и независимый проверяющий оценивают смысловую релевантность по цитируемому
   содержимому страниц.

Приоритет источников:

1. Официальный сайт конференции.
2. Официальный сайт организатора.
3. Авторитетный вторичный источник.

Вторичные данные не могут незаметно перезаписать подтверждённые официальные значения. Старые
значения сохраняются в истории изменений.

Страница-каталог, например список мероприятий ESO или IAU, сохраняется в «Источники». Найденные
на ней конкретные мероприятия становятся отдельными кандидатами, а каталог не превращается в
фиктивную конференцию.

## Отслеживание дедлайнов

ConfPlanner умеет хранить:

- открытие регистрации;
- раннюю регистрацию;
- окончание регистрации;
- подачу тезисов;
- подачу устных докладов;
- уведомление о принятии;
- оплату;
- другие подтверждённые сроки.

Каждое значение хранит URL источника, класс источника, короткую цитату, время наблюдения и
статус проверки.

Точная дата хранится как календарная дата. Срок вида «май 2027» хранится как ориентировочный
месяц без выдуманного числа.

Ежедневная задача запускается в `REMINDER_HOUR`. Для точных дат по умолчанию используются
пороги:

```dotenv
REMINDER_DAYS=30,14,7,3,1,0
```

Один порог отправляется только один раз. После простоя бот не воспроизводит все пропущенные
уведомления, а отправляет только актуальное.

## Автоматическое расписание

Каждый понедельник в `DISCOVERY_HOUR` запускается единый цикл проверки и поиска.

Одна и та же неизменившаяся страница повторно проверяется не чаще
`MONITORING_INTERVAL_HOURS`. Значение по умолчанию — 72 часа. Кнопка «Проверить сейчас»
обходит этот интервал.

Перед обращением к модели страница сравнивается с кешем по ETag, Last-Modified и хешу очищенного
текста. Неизменившаяся страница не должна повторно расходовать токены.

Для повторяющихся нестандартных сайтов могут использоваться версионированные декларативные
CSS/regex-рецепты. Они не исполняют код. При изменении вёрстки обработка возвращается к
универсальному парсеру.

## Резервное чтение страниц

Если прямое соединение с публичным сайтом не устанавливается, ConfPlanner может прочитать эту
же страницу через `READER_FALLBACK_URL`, по умолчанию `https://r.jina.ai`.

В Reader передаётся только URL публичной страницы. Сообщения Telegram, память и API-ключи туда
не отправляются.

Чтобы отключить резервное чтение:

```dotenv
READER_FALLBACK_URL=
```

JavaScript-only страницы браузером не рендерятся.

## Работа с Docker

Запуск и обновление:

```bash
docker compose up -d --build
docker compose ps
```

Логи приложения:

```bash
docker compose logs --tail=100 -f confplanner
```

Логи поиска:

```bash
docker compose logs --tail=100 -f searxng
```

Пересоздание после изменения `.env` или исходников:

```bash
docker compose up -d --build --force-recreate confplanner
```

Остановка и запуск приложения:

```bash
docker compose stop confplanner
docker compose start confplanner
```

Alembic автоматически применяет миграции при старте. Контейнер работает от непривилегированного
пользователя, с read-only root filesystem, отключёнными capabilities, `no-new-privileges`,
writable volume `/data` и tmpfs `/tmp`.

## Резервное копирование

Перед копированием SQLite остановите процесс записи:

```bash
docker compose stop confplanner
docker volume ls
docker run --rm \
  -v confplanner_conference_data:/data \
  -v "$PWD":/backup \
  alpine cp /data/conference_scout.db /backup/conference_scout.db
docker compose start confplanner
```

Префикс имени volume зависит от имени Compose-проекта. Проверьте его через `docker volume ls`.
Резервную копию необходимо проверить отдельно до обновления или удаления исходной базы.

## Проверка подключения модели

Smoke-команда делает настоящий запрос и может расходовать облачный лимит. Запускайте её только
явно:

```bash
uv run python scripts/smoke_model.py --profile ollama-cloud --model gpt-oss:20b
uv run python scripts/smoke_model.py --profile llm-local --model YOUR_MODEL_ID
```

Команда проверяет наличие модели и один безопасный tool call. Ключи и полное тело ответа API не
печатаются.

## Безопасность

- `.env` исключён из Git;
- секреты не сохраняются в prompts, MCP-ответах или Telegram-ошибках;
- внешние страницы считаются недоверенными данными;
- содержимое сайта не может изменить системную политику или список инструментов;
- fetcher блокирует loopback, private, link-local и metadata-адреса для внешних страниц;
- собственный `LLM_LOCAL_BASE_URL` настраивается отдельным модельным шлюзом и может находиться в
  приватной сети;
- MCP доступен только внутри контейнера;
- SearXNG не публикует порт на хост;
- healthcheck выполняет запрос к базе и не расходует токены модели.

## Диагностика

### TelegramConflictError

Ошибка `terminated by other getUpdates request` означает, что один токен одновременно используют
два процесса. Оставьте запущенным только один экземпляр:

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}'
docker compose up -d --force-recreate confplanner
```

### Не загружается список локальных моделей

Проверьте:

- правильность `LLM_LOCAL_BASE_URL`;
- наличие `/v1`;
- доступность адреса из Docker;
- ответ `GET /v1/models`;
- правильность Bearer-ключа;
- наличие выбранной модели в `/models`;
- поддержку OpenAI tool calls.

Логи:

```bash
docker compose logs --since=15m confplanner
```

### Поиск работает медленно

Отдельные движки SearXNG могут получать CAPTCHA, rate limit или timeout. Это не всегда означает
отказ всего поиска. Проверьте оба сервиса:

```bash
docker compose logs --since=30m confplanner
docker compose logs --since=30m searxng
```

### Не появились дедлайны

Откройте карточку конференции и выберите «Проверить сейчас». Данные не записываются без
цитируемого источника. Обновлению могут мешать недоступный сайт, JavaScript-only страница,
отсутствующий текст дат или невалидный структурированный ответ модели.

Если у вас есть надёжная ссылка, но автоматическое чтение невозможно, добавьте срок вручную
через подтверждаемое действие.

## Ограничения

- проект рассчитан на одного владельца;
- JavaScript-only страницы не рендерятся;
- качество извлечения зависит от страницы и выбранной модели;
- локальная модель должна иметь достаточно RAM/VRAM и поддерживать tools;
- некоторые сайты блокируют автоматические запросы;
- точный процент лимита Ollama недоступен через используемый model API;
- внутренний MCP не является публичным multi-tenant API.
