# ConfPlanner

ConfPlanner — персональный self-hosted Telegram-агент для поиска научных конференций,
контроля дедлайнов и заметок владельца. Один deployment обслуживает одного владельца;
сообщения остальных пользователей отклоняются до запуска обработчиков.

## Features

- Сам Telegram-бот является AI-чатом: ordinary text сразу получает ответ агента, отдельной
  кнопки «AI-чат» нет.
- Ollama Cloud и LLM Hub с выбором модели через `/model` без перезапуска.
- Ограниченный agent loop с внутренним MCP v2, памятью диалога и SQL-графом знаний.
- Пользовательские заметки и правила: например, «эта конференция приоритетная» или
  «не предлагай мероприятия в США».
- Любое агентское изменение сначала становится expiring pending action и выполняется только
  после подтверждения владельцем в Telegram.
- Поиск через внутренний SearXNG, SSRF-safe загрузка страниц, provenance дедлайнов,
  дедупликация, мониторинг и напоминания.

## Architecture

Один async Python-процесс запускает aiogram polling, APScheduler и MCP Streamable HTTP на
`127.0.0.1`. MCP-порт не публикуется Docker Compose. SQLite остаётся источником истины для
конференций, связей, истории чата, памяти, выбранной модели и pending actions. SearXNG работает
вторым внутренним сервисом. Модель не получает shell, filesystem, raw SQL, secrets,
произвольный fetch URL или unrestricted web tool.

Длительное исследование выполняет гибридная мультиагентная система. Координатор строит
ограниченный сохраняемый workflow, исследователь извлекает факты, независимый проверяльщик
сверяет цитаты, а детерминированный валидатор решает, какие значения разрешено записать.
Запуски, задачи, артефакты и безопасные события прогресса находятся в SQLite, поэтому после
перезапуска продолжаются только незавершённые и retryable-задачи; готовые шаги не повторяются.
В Telegram видны безопасные фазы вроде поиска, открытия источника и проверки, но не скрытые
рассуждения модели, секреты или полный текст внешней страницы.

## How it works

Агент собирает системную политику, релевантную память, summary и последние сообщения. Модель
может ответить сразу либо вызвать один из строго описанных MCP-инструментов. Аргументы проходят
JSON Schema validation. Чтение выполняется сразу; `propose_*` лишь создаёт pending action.
Подтверждение вызывает детерминированный Python-сервис ровно один раз. Сообщение «сохранено»
или «обновлено» формируется только из committed persistence receipt после повторного чтения
записанных строк; текст модели без такой квитанции не считается результатом. Turn ограничен числом
шагов, tool calls, размером контекста/результатов и общим timeout.

Поиск конференций остаётся source-backed: Python строит запросы, а SearXNG постранично
возвращает реальные URL без общего лимита в 20 сайтов. Первичный поиск быстро сохраняет ссылки
как непроверенных кандидатов. Безопасный fetcher открывает только выбранные моделью результаты,
после чего первый структурированный проход извлекает цитируемые факты, а второй независимо
проверяет их по переданным фрагментам. Pydantic валидирует оба ответа. Ollama Cloud не
гарантирует provider-enforced structured output, поэтому в приложении сохранены validation и
bounded retries.

## Requirements

- Docker Engine и Compose v2;
- Telegram bot token и numeric Telegram ID владельца;
- хотя бы один model profile: Ollama Cloud key или LLM Hub endpoint и API key;
- для разработки: Python 3.12+ и `uv`.

## Quick start

```bash
git clone YOUR_REPOSITORY_URL ConfPlanner
cd ConfPlanner
cp .env.example .env
# заполните TELEGRAM_BOT_TOKEN, OWNER_TELEGRAM_ID и model profile
docker compose up -d
docker compose logs -f confplanner
```

При старте Alembic автоматически обновляет свежую или известную legacy-базу без удаления
существующих тем, конференций, источников и истории.

## Telegram bot creation

Создайте бота через `@BotFather`, запишите token в `TELEGRAM_BOT_TOKEN`, а свой numeric ID —
в `OWNER_TELEGRAM_ID`. Не отправляйте token или model API key в чат бота.

## Model configuration

### Ollama Cloud

```dotenv
OLLAMA_CLOUD_BASE_URL=https://ollama.com
OLLAMA_CLOUD_API_KEY=YOUR_OLLAMA_CLOUD_API_KEY
```

Cloud показывает только пересечение ответа `/api/tags` и настроенного allowlist. Free usage credits
can be used with указанными в `.env.example` моделями; доступность и условия тарифа
могут измениться на стороне Ollama. Добавление платных credits не выполняется приложением.

### Ollama Free usage

Кнопка «Настройки» в Telegram показывает локально зафиксированные запросы и токены по каждой
модели Ollama Cloud за текущие сутки и месяц. Это наблюдения ConfPlanner, а не остаток или процент
лимита аккаунта. Кнопка «Точный Free usage в Ollama» открывает официальный экран
`https://ollama.com/settings/usage`, где Ollama показывает актуальный процент использования.

«Временное ограничение» означает ответ HTTP 429 и само по себе не доказывает исчерпание Free
usage. Подтверждённое исчерпание показывается отдельно после соответствующего ответа провайдера.
Через выбор модели бот предлагает только модели из `OLLAMA_CLOUD_FREE_MODELS`; автоматического
перехода на платную модель нет.

ConfPlanner не получает процент использования аккаунта из Ollama API и не пытается извлекать его
из веб-страницы. Если в аккаунте Ollama включены платные credits, приложение не может запретить их
списание — это необходимо контролировать в настройках самого аккаунта Ollama.

### LLM Hub

```dotenv
LLM_HUB_BASE_URL=http://192.168.0.169:1337/v1
LLM_HUB_API_KEY=YOUR_LLM_HUB_API_KEY
```

LLM Hub должен предоставлять `/v1/models` и `/v1/chat/completions`; ключ передаётся как Bearer
token. Профиль скрыт из `/model`, пока `LLM_HUB_BASE_URL` не настроен. Логин и пароль веб-панели
не используются агентом.

## Telegram commands

- `/start` — краткая справка; после неё просто пишите запросы обычным текстом;
- `/model` — выбрать profile/model и проверить tool-calling capability;
- `/new` — начать новый диалог, не удаляя долгосрочную память;
- `/memory` — показать активные заметки и правила;
- `/forget ID` — предложить удалить запись памяти с подтверждением;
- `/help` — подсказка по командам.

Кнопка «Настройки» показывает состояние Ollama Free usage, локальную статистику и ссылку на
официальный экран лимита.

Модель без tool calling остаётся доступной с пометкой «только чат». Исчезнувшая из API модель
не выбирается повторно; выполните `/model` и выберите актуальную.

## Memory and confirmations

История диалога хранится в SQLite и при росте заменяется безопасным summary. Долгосрочная память
хранит исходный текст, валидированное правило, scope (`GLOBAL`, `TOPIC`, `CONFERENCE`) и
provenance. SQL knowledge graph проецирует связи тем, конференций, дедлайнов, источников,
подписок и заметок без отдельной graph DB.

Добавление темы/источника, tracking/archive, сохранение/удаление памяти и discovery требуют
кнопки «Подтвердить». Просроченное, отменённое, чужое или уже выполненное действие не исполняется.

## Model smoke check

Smoke-команда делает реальный запрос и может расходовать Cloud credits, поэтому обычные тесты её
не запускают. Выполняйте только явно:

```bash
uv run python scripts/smoke_model.py --profile llm-hub --model YOUR_MODEL_ID
uv run python scripts/smoke_model.py --profile ollama-cloud --model gpt-oss:20b
```

Profile IDs: `ollama-cloud`, `llm-hub`. Команда проверяет список моделей и
один harmless tool call, но никогда не печатает ключ или upstream response body.

## SearXNG

Compose запускает SearXNG без host-порта. Приложение обращается к нему по
`http://searxng:8080`. Внешние страницы остаются недоверенными данными и не могут менять policy
или список инструментов агента.

## Configuration

Все переменные перечислены в `.env.example`. Основные лимиты: `AGENT_MAX_STEPS`,
`AGENT_MAX_TOOL_CALLS_PER_STEP`, `AGENT_TIMEOUT_SECONDS`, `AGENT_MAX_CONTEXT_CHARS` и
`AGENT_MAX_TOOL_RESULT_CHARS`. MCP должен оставаться на `MCP_HOST=127.0.0.1`. Изменения `.env`
требуют рестарта контейнера; выбор через `/model` сохраняется без рестарта.

Модели ролей задаются независимо через `AGENT_SUPERVISOR_MODEL`, `AGENT_RESEARCH_MODEL`,
`AGENT_VERIFIER_MODEL` и `AGENT_FALLBACK_MODEL`; пустое значение использует активную модель
пользователя. `AGENT_WORKFLOWS_ENABLED=true` включает долговечные workflow и восстановление при
старте. Для аварийного отката установите `false`: обычный чат, старый discovery и мониторинг
останутся доступны, но новые workflow и их автоматическое восстановление запускаться не будут.

### Локальная дата и часовой пояс

Задайте IANA-зону сервера явно:

```dotenv
APP_TIMEZONE=Europe/Moscow
```

При старте создаётся единый application clock. В «Настройках» бот показывает выбранную зону и
локальные дату/время запуска. Текущая локальная дата передаётся агенту, определяет границу
«будущих» конференций и дедлайнов и используется планировщиком. Поэтому событие, завершившееся
до этой даты, не должно предлагаться как актуальный кандидат.

## Docker deployment

```bash
docker compose up -d
docker compose ps
docker compose logs -f confplanner
```

Приложение использует long polling и не публикует входных портов. Контейнер работает non-root,
с read-only root filesystem, dropped capabilities, `no-new-privileges`, writable `/data` и
tmpfs `/tmp`. Ни MCP, ни SearXNG наружу не опубликованы.

## Trusted sources

`DOMAIN example.org` добавляет `site:`-ограничение, а `PAGE https://example.org/events` — каталог
для проверки. Trusted не означает official: вторичные даты сохраняются с соответствующим
provenance и verification flag.

## Topics

Темы можно добавить разговором с агентом или старым shortcut «Мои темы». Каноническое имя,
описание и keywords валидируются, а запись появляется только после подтверждения.

## Discovery

Попросите агента найти конференции или нажмите shortcut «Найти конференции». Ручной поиск и
автоматический поиск каждый понедельник запускают один цикл: проверяют отслеживаемые конференции,
пересматривают отложенные карточки, затем ищут новые результаты с пагинацией. Результаты
сохраняются как долговечные кандидаты и показываются по одному с кнопками «Отслеживать»,
«Подробнее», «Пропустить» и «Отклонить». Только «Отслеживать» создаёт pending action; после
подтверждения сохранённый проверенный снимок переносится в карточку конференции без второго
запроса к сайту и модели; затем включается отслеживание.
Перезапуск бота не меняет candidate ID. Просроченный, пропущенный или уже импортированный
кандидат возвращает отдельное сообщение.

Во время долгого поиска одно Telegram-сообщение показывает текущую фазу: страницу поиска,
проверку выбранного источника и число полученных кандидатов. Если внешний сайт или модель
отвечает медленно, статус обновляется heartbeat-сообщением. Повторный запрос из того же чата не
запускает параллельный дубликат. Поиск может переходить на следующие страницы SearXNG и менять
русские/английские формулировки; глубоко проверяются наиболее релевантные кандидаты, а не каждая
ссылка выдачи.

### Снимок проверки кандидата

После «Проверить» кандидат получает сохраняемый снимок: нормализованное название, время и место
проведения, официальный URL, дедлайны с цитатами, оценку релевантности и замечания проверяльщика.
Кнопка «Добавить» использует именно этот снимок и не вызывает сайт и модель второй раз. Если
снимок устарел, повреждён или кандидат уже неактивен, запись не выполняется и требуется новая
проверка.

### Двухступенчатая проверка релевантности

Сначала детерминированный фильтр проверяет дату события и совпадение с ключевыми словами тем
владельца. Затем исследователь и независимый проверяльщик оценивают смысловую релевантность по
цитируемому содержимому страницы. Кандидат ниже `MIN_RELEVANCE_SCORE` остаётся вне импорта;
доступная страница каталога может быть раскрыта в отдельные карточки конференций и проверена по
внутренним ссылкам того же домена.

## Deadline tracking

### Ручные дедлайны

Фраза вроде «для IMBASE 2027 установи дедлайн регистрации на май 2027» сначала ищет сохранённую
конференцию по названию. При нескольких совпадениях агент обязан показать ID и дождаться выбора.
Затем создаётся подтверждаемое действие; только кнопка «Подтвердить» записывает срок в SQLite.
Точный день хранится как exact date, а месяц без дня — как `approximate_year` и
`approximate_month` со статусом `tentative`. Повтор той же операции не создаёт дубль.

Единый понедельничный цикл запускается в `DISCOVERY_HOUR`, но неизменившуюся страницу повторно
проверяет не чаще интервала `MONITORING_INTERVAL_HOURS` — по умолчанию раз в 72 часа. Кнопка
«Проверить сейчас» обходит этот интервал. Тот же конвейер способен заполнить пустую карточку:
даты проведения, место, источники и отсутствующие дедлайны, а не только изменить уже созданный
срок.

Перед вызовом модели страница сравнивается с HTTP-кешем по ETag, Last-Modified и хешу текста.
Неизменившаяся страница не расходует токены. Для повторяющихся нестандартных сайтов используются
версионированные декларативные рецепты CSS/regex без исполнения кода; при изменении вёрстки
рецепт помечается деградировавшим, и обработка возвращается к универсальному парсеру.

Если прямое безопасное соединение с публичным сайтом не устанавливается, мониторинг может
прочитать эту же публичную страницу через `READER_FALLBACK_URL` (по умолчанию
`https://r.jina.ai`). В Reader передаётся только URL страницы; сообщения Telegram, память и
ключи моделей туда не отправляются. Пустое значение отключает резервное чтение. Каталоги вроде
годового списка ESO распознаются отдельно: URL переносится в «Источники», а конкретные события
появляются в очереди кандидатов вместо фиктивной отслеживаемой «конференции-каталога».

Приоритет источников: официальный сайт конференции, официальный сайт организатора, затем
доступный авторитетный вторичный источник. Вторичные данные явно маркируются и не могут
перезаписать подтверждённые официальные. Когда официальный сайт снова доступен, его сведения
получают приоритет, а предыдущее значение остаётся в истории.

Срок вида «май 2027» хранится как ориентировочный месяц без выдуманного дня. Он показывается в
списке и создаёт одно напоминание в первый день указанного месяца. Для точных дат ежедневная
задача в `REMINDER_HOUR` использует пороги `REMINDER_DAYS=30,14,7,3,1,0`; один и тот же порог
повторно не отправляется, а после простоя приходит только одно актуальное уведомление. Каждое
значение хранит URL, класс источника, короткую цитату, время наблюдения и статус проверки.

Раздел «Конференции» и его карточки всегда читают SQLite, а не утверждения из истории чата.
Там доступны текущие дедлайны, доказательства, история изменений и ручная проверка.

Для диагностики используйте:

```bash
docker compose logs --since=30m confplanner
docker compose logs --since=30m searxng
```

CAPTCHA или timeout отдельного поискового движка SearXNG не означает потерю уже сохранённых
данных. После трёх последовательных неудач мониторинга бот уведомляет владельца безопасным кодом
ошибки без тела upstream-ответа или секретов.

## Backups

Перед файловой копией остановите writer:

```bash
docker compose stop confplanner
docker run --rm -v confplanner_conference_data:/data -v "$PWD":/backup alpine \
  cp /data/conference_scout.db /backup/conference_scout.db
docker compose start confplanner
```

Имя volume уточните через `docker volume ls`. Для восстановления остановите сервис, замените
`/data/conference_scout.db`, сохраните владельца/права и снова запустите приложение. Всегда
проверяйте backup отдельно до обновления.

## Security

Secrets находятся только в ignored `.env`, не сохраняются в БД, prompts, MCP results или
Telegram errors. Не коммитьте `.env`. Fetcher разрешает лишь HTTP(S) public destinations,
проверяет DNS/redirects и блокирует private, loopback, link-local и metadata addresses. MCP
доступен только внутри container loopback. Healthcheck выполняет только `SELECT 1` и не вызывает
модель, поэтому не расходует credits.


SQLite async tests могут требовать обычных thread permissions из-за worker thread `aiosqlite`.

## Testing

Обычный suite использует fake model/search/fetch/Telegram boundaries и временные SQLite-базы —
credentials, интернет и credits не нужны. Integration tests покрывают Alembic compatibility,
discovery, monitoring, MCP handshake и model→tool→confirmation→domain flow.

## Limitations

JavaScript-only страницы не рендерятся. Качество extraction зависит от модели. Локальный endpoint
должен быть доступен контейнеру и иметь достаточную RAM/VRAM. Это намеренно single-owner service;
MCP не является публичным multi-tenant API.

## Roadmap
